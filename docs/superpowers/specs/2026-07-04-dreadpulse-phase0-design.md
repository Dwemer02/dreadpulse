# DREADPULSE Phase 0 — 전투 시뮬레이터 설계 문서

- 날짜: 2026-07-04
- 근거 문서: [DREADPULSE_GDD.md](../../DREADPULSE_GDD.md) (v0.1)
- 상태: 사용자 승인 대기

## 1. 목적과 범위

기획서 디자인 필라 #1 **"되먹임 폭발이 재밌는가"** 를 숫자로 검증하는 전투 시뮬레이터.
기획서는 "그래픽 없음"이라 했으나, 사용자 결정으로 **간단한 디버그 시각화를 포함**한다.

### 목표 (Goals)
- 심박 클럭 / 펄스 전파 / charge 발동 / 자원 3종(steam, ammo, ichor)의 전투 루프 구현
- 부품 12종(강철 6 + 생체 6) + 융합 3종
- 1:1 자동 전투, 승패 판정, 틱 단위 전투 로그
- 결정론적(고정 틱 + 시드 RNG) 시뮬레이션 → 배치 통계 검증 가능
- 검증 지표 3종을 자동 리포트로 출력
- 디버그 씬: 부품 보드 + 펄스 플래시 + 게이지 + 로그 (ColorRect/Label 수준)

### 비목표 (Non-Goals) — Phase 1 이후로 명시적 연기
- 배선 거리에 따른 펄스 지연/감쇠 (GDD §5 배선 퍼즐) → Phase 2
- 포식 드래프트, 맵 노드, 정비 UI → Phase 2
- 셰이더/아트/로어 텍스트 → Phase 3
- 부품 20~30종 확장, 정밀 밸런싱 → Phase 1
- 존(갑판/내부/흘수선) 태그 시너지 → Phase 1~2 (데이터 필드만 예약)

## 2. 아키텍처 — 3층 분리

```
res://
├── sim/                     # 순수 로직. Node/씬 참조 금지. 결정론 보장.
│   ├── combat_sim.gd        # 전투 1판: 틱 루프, 양측 갱신, 승패 판정, 이벤트 방출
│   ├── ship_state.gd        # 함선: 부품 배열 + 배선 그래프 + hull + 자원 풀
│   ├── part.gd              # 부품 런타임 상태: charge, hull, 영구 스택, 저장 펄스
│   ├── pulse_network.gd     # 펄스 전파(BFS), 신경절 복제, 낭포 흡수
│   ├── parts_catalog.gd     # 부품 정의(정적 데이터): 효과 타입 + 파라미터
│   └── builds/*.json        # 테스트 빌드: 부품 목록 + 배선 + 융합
├── tests/
│   ├── run_batch.gd         # 헤드리스 배치 러너(SceneTree 스크립트)
│   └── out/                 # 통계 리포트, CSV (gitignore)
└── debug/
    ├── battle_view.tscn     # 디버그 시각화 씬
    └── battle_view.gd       # 이벤트 스트림 구독 → 그리기
```

**의존 방향은 한 방향뿐이다**: `debug/`와 `tests/`가 `sim/`을 사용한다. `sim/`은
아무것도 모른다. 시뮬레이션은 매 틱 **이벤트 배열**(아래 §6)을 방출하고, 디버그 씬은
그걸 그리기만, 배치 러너는 그걸 집계만 한다. 이 코어가 그대로 Phase 2+의 실전 전투 엔진이 된다.

## 3. 시뮬레이션 모델

### 3.1 시간
- 고정 틱 `TICK_DT = 0.05초`. 전투 시간 상한 300초(초과 시 잔여 hull 비율로 판정승).
- 심장은 부동소수 누적 타이머: `time_since_pulse += TICK_DT`, `>= pulse_interval`이면
  펄스 방출 후 잔여분 이월. 아드레날린 포의 `-0.05s`가 정확히 반영된다.
- `pulse_interval` 하한 0.5s. 하한 상태에서 추가 감소 효과 발생 시 감소 대신
  **과부하 자해**(자함 hull 피해, 파라미터) — GDD §3.3.

### 3.2 결정론
- 모든 확률은 `RandomNumberGenerator`에 시드를 주입해 사용. 시뮬레이션 외부에서
  `CombatSim.new(build_a, build_b, seed)`로 생성.
- 같은 (빌드A, 빌드B, 시드) = 항상 같은 결과. 배치 러너는 시드만 바꿔 N판 실행.
- 양측 갱신 순서 고정: 매 틱 [A 심장→A 발동→B 심장→B 발동→사망 판정].
  동시 격침 시 무승부 처리.

### 3.3 펄스 전파
- 배선은 무방향 그래프(부품 = 노드, wire = 엣지). 심장에서 BFS, 즉시 전파(지연 없음).
- 한 펄스당 각 부품은 1회만 수신(visited set). 수신 시 `charge += pulse_power`(기본 1).
- **신경절(Ganglion)**: 펄스 통과 시 25% 확률로 자신을 기점으로 **추가 펄스 1회** 방출
  (새 BFS, 새 visited set). 연쇄 복제 허용하되 펄스당 복제 깊이 상한 8 (무한 루프 방지).
- **낭포(Cyst)**: 펄스를 흡수해 저장하고 **하류로 전달하지 않는다**(BFS가 낭포에서 끊김).
  파괴되거나 저장량 임계 도달 시 저장량 비례 폭발(적함 피해).
- **부심장(Ancillary Heart)**: 독립 타이머의 제2 펄스원(자신을 기점으로 BFS).
  주심장과 같은 틱에 방출이 겹치면 두 펄스를 방출하지 않고 주심장 기점의
  **공명 펄스 1회**(`pulse_power = 2`)로 통합한다.

### 3.4 발동과 자원
- `charge >= required_charge` → 발동 시도. 자원 소모형은 부족 시 **불발**:
  charge 유지(기본 정책, 부품별 재정의 가능), `misfire` 이벤트 방출.
- 자원 풀은 함선 단위: `steam`(생산-소비), `ammo`(초기 비축 + 탄약고 가산, 생산 없음
  → 고갈 압박이 자원 설계 검증 지표), `ichor`(피격/적중 시 축적. Phase 0에서는
  소비처 없음 — 축적량만 기록·표시하는 예약 자원).

### 3.5 표적과 피해
- 기본: 무기는 **적함 hull**을 직접 타격 (부품 개별 hull은 존재하되 기본 비표적).
- **눈알(Eye)**: 배선으로 연결된 무기에 부품 조준 부여 — 적의 지정 우선순위 부품
  (기본: 탄약고)을 타격. 부품 hull 0 → 파괴 이벤트 (탄약고 파괴 = **유폭**: 소유 함에 광역 피해).
  우선순위 부품이 적함에 없거나 전부 파괴되면 함 hull 직접 타격으로 폴백.
- **장갑구획**: 부품 조준 피해에 대해 인접 부품 피해 30% 흡수(자신이 대신 받음).
- **아가미**: 함 피격 시 받은 피해의 절반을 steam으로 전환.

### 3.6 부품 효과 시스템 (확장성의 핵심)
상속 계층 대신 **효과 타입 enum + 파라미터 사전** 방식.

```gdscript
# parts_catalog.gd 항목 예시
"main_turret": {
    "name": "주포탑", "kind": "steel", "hull": 10, "required_charge": 3,
    "effects": [
        {"type": Effect.FIRE_PROJECTILE, "damage": 8,
         "cost": {"steam": 1, "ammo": 1}}
    ],
    "graft_slot": true
}
```

효과 타입(Phase 0): `PRODUCE_RESOURCE`, `FIRE_PROJECTILE`, `ADJACENT_DAMAGE_BUFF`,
`ADJACENT_CHARGE_DISCOUNT`, `EXTRA_PULSE`, `ABSORB_ADJACENT_DAMAGE`, `PULSE_REPLICATE`,
`PERMANENT_STACK_ON_HIT`, `PART_TARGETING`, `DAMAGE_TO_RESOURCE`, `STORE_PULSE`,
`SECOND_HEART`, `ON_DEATH_EXPLODE`, `INTERVAL_REDUCE_ON_HIT`(융합).
새 부품 = 카탈로그에 데이터 항목 추가. Phase 1의 20~30종 확장이 데이터 작업이 된다.

### 3.7 융합 (graft)
융합은 강철 부품에 `graft: "생체부품ID"` 필드를 붙이면 카탈로그의 **융합 테이블**이
결과 효과 목록으로 치환하는 방식. Phase 0 구현 3종:

| 융합 | 결과 | 핵심 효과 |
|---|---|---|
| 주포탑+신경삭 | 아드레날린 포 | 적중 시 `pulse_interval -= 0.05s` (하한 0.5s, 초과 시 자해) |
| 보일러+아가미 | 혈압 보일러 | steam 생산량 = 기본 + 이번 전투 피격 횟수 비례 |
| 탄약고+낭포 | 유폭 심장 | ammo 대신 펄스 저장, 임계 도달 시 연결 포탑 일제사격 |

## 4. 부품 카탈로그 초기 수치 (전부 플레이스홀더, GDD §3.2 준거)

강철: 보일러(2펄스마다 steam+1) / 주포탑(charge3, steam1+ammo1 → 피해8) /
탄약고(패시브: 인접 포탑 피해+2, ammo 비축+15, 파괴 시 유폭 자함 20) /
자동장전기(패시브: 인접 포탑 required_charge −1, 하한 1) /
증기터빈(charge2, steam3 → 즉시 추가 펄스 1회) / 장갑구획(hull 40, 인접 흡수 30%).

생체: 신경절(통과형 25% 복제) / 촉수(charge2, 피해3, 적중마다 이번 전투 피해+1) /
눈알(패시브: 연결 무기 부품 조준) / 아가미(피격 피해 50% → steam) /
낭포(축전형, 임계 10, 폭발 = 저장량×3 피해) / 부심장(interval 1.5s, 공명 시 power 2).

공통 시작값: 함 hull 100, 주심장 `pulse_interval = 1.0s`, 시작 ammo 20, 시작 steam 0.

## 6. 이벤트 스트림 (sim → 소비자 계약)

매 틱 `CombatSim.step()`이 이벤트 배열을 반환. 각 이벤트는 Dictionary:
`{tick, side, type, ...payload}`. 타입: `pulse_emitted`, `pulse_arrived`, `pulse_stored`,
`part_fired`, `misfire`, `damage_dealt`, `part_destroyed`, `resource_changed`,
`interval_changed`, `stack_gained`, `resonance`, `explosion`, `battle_end`.

- 디버그 씬: 이벤트를 그대로 시각 효과/로그 라인으로 변환.
- 배치 러너: 이벤트를 집계해 통계 산출. 텍스트 전투 로그도 이벤트의 문자열 변환일 뿐.

## 7. 검증 지표 (기획서 §10 → 자동 리포트)

`tests/run_batch.gd`를 헤드리스로 실행(`godot --headless --script`). 4개 빌드 교차
대전 × 시드 50개. 출력: 콘솔 요약 + `tests/out/*.csv`.

1. **지수 곡선**: overdrive 빌드의 10초 구간별 펄스 수. 후반 구간/초반 구간 비율이
   단조 증가하면 합격. CSV로 틱별 누적 펄스 기록.
2. **촉수 추월**: bloodpressure(촉수 포함) vs 고내구 더미 장기전에서 촉수 누적 피해가
   주포 누적 피해를 추월하는 시점(초) 출력. 60초 내 추월이 존재해야 합격.
3. **자원 고갈 압박**: pure_steel에서 보일러 1개를 제거한 변형 빌드의 불발률(%) 비교.
   유의미한 불발(>15%)이 발생해야 합격.

+ 기본 건전성: 4빌드 총당 승률 표 — 한 빌드가 전 매치업 90% 이상 승리하면 밸런스 경고.

## 8. 디버그 씬

한 화면 구성: 좌/우 함선 보드(부품 = 계통색 박스: 강철=청회, 생체=자주 / charge
게이지 바 / 발동 시 플래시), 중앙 상단 양측 hull 바 + steam/ammo/ichor 카운터,
하단 스크롤 전투 로그, 우상단 배속(1x/4x/최대) + 일시정지 + 시드/빌드 선택 드롭다운.
전투 진행은 `_process`에서 배속만큼 `sim.step()`을 호출하는 방식 — 렌더 프레임과
시뮬레이션이 분리되어 결정론이 유지된다.

## 9. 에러 처리

- 빌드 JSON 로드 시 검증: 미지의 부품 타입, 심장 부재, 고아 노드(배선 미연결),
  유효하지 않은 융합 조합 → 명시적 에러 메시지와 함께 로드 거부.
- 시뮬레이션 내부 불변식 위반(음수 자원, 파괴된 부품 발동)은 `push_error` + 전투 중단.
- 무한 전투 방지: 300초 상한 + 펄스 복제 깊이 상한 8.

## 10. 테스트 전략

- GUT 등 외부 프레임워크 없이, `tests/run_batch.gd`가 통계 검증을 겸한다.
  추가로 `tests/run_unit.gd`에 순수 로직 단위 검증(펄스 BFS, 발동/불발, 융합 치환,
  결정론 재현성: 같은 시드 2회 실행 결과 동일)을 assert 기반으로 작성.
- 헤드리스 실행이 CI 없이도 한 명령으로 가능해야 한다.
